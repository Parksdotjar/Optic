# Version 3 — Professional Audio

## Main Goal

Turn the working V1/V2 audio foundation into edit-ready, independently controllable tracks with dependable long-session synchronization. This milestone starts only after basic Minecraft and microphone capture actually work. All capabilities below are planned until separately validated.

## User Experience

A normal recording retains sensible default audio automatically. A creator can optionally select a microphone, adjust gain, mute it and inspect a small peak meter. Advanced track choices allow Minecraft Master, Microphone and, on supported integrations, Voice Chat as separately named tracks. Editors should not need to repair growing A/V drift or remove unrelated desktop sounds.

## New Features

- Persistent microphone selection, input gain, mute, peak indication, clipping warnings and bounded reconnect behavior.
- Explicit track enablement and readable track names/roles in exported files.
- Optional Simple Voice Chat integration after its public API and capture semantics are investigated.
- Feasibility study and limited support for clean category separation: music, players, hostile/passive mobs, blocks, weather, UI and ambient audio. Publish supported categories; do not invent silent substitute tracks.

## Technical Work

Extend AudioCapture and AudioEncoder around timestamped audio blocks and a shared session clock. Each block needs source identity, channel layout, sample format, sample count and a timing reference. Use per-source bounded buffers with preallocated block pools. Device callbacks must not wait on disk, encoding, locks held by UI code or Minecraft rendering.

Define where Minecraft Master is tapped relative to volume, spatialization and effects. Prefer an existing clean mix/tap boundary over duplicating the whole sound engine. Investigate whether categories can be separated without changing what the player hears. A source's nominal category is not proof of a correct isolated output.

For voice chat, determine remote voices, local mic monitoring, positional processing and playback inclusion. Specify whether Master includes voices; offer a clearly described split arrangement that avoids accidental double mixing. Bind an adapter only when a supported integration is present and enabled.

Track audio clocks against monotonic video time. Estimate device drift and use bounded resampling or explicit discontinuities, not periodic arbitrary drops that create clicks. Record reconnect gaps as silence on the original timeline. Preserve track schema, offsets and source diagnostics in V2 manifests for recovery.

## Performance Work

Audio UI meters read decimated summaries, not sample streams. Gain, resampling and encoding belong off-thread; category-disabled mode must not incur category-processing costs. Make queue duration and maximum track count explicit.

Provisional targets: measured A/V alignment and inter-track error no greater than 20 ms throughout a four-hour supported-device session; no accumulating drift beyond that window. Verify with known visual/audio impulses and account for test equipment latency. Under declared steady-state load, no missing sample blocks or audible discontinuities. Audio queues should have a bounded latency budget initially no greater than 250 ms per source; revise only with evidence and document the tradeoff.

With advanced audio disabled, stay within V2 benchmark noise. With basic multi-track audio enabled, investigate more than 5% p95/p99 game-frame regression or 3% loss in 1% lows against matched V2 capture. Measure CPU, memory, audio overruns and disk throughput separately.

## UI / UX

Keep microphone ON/OFF in simple settings. Place device, gain, mute, meter and track selection in a compact audio detail screen. Warn about clipping only after a sustained threshold, not every peak. Reconnect feedback should be brief. Do not expose compressor chains, buses or a DAW-style mixer.

## Reliability

Preserve stable track identity when devices reconnect. Never switch silently to another microphone after the selected one disappears; make any default-device-following behavior explicit. Device denial, format mismatch or voice-chat failure should isolate that source and keep video and healthy sources running. Recover sidecars independently.

Known risks: driver clock drift, Bluetooth profile changes, inconsistent latency reporting, double-captured voice chat, and category taps that miss effects or alter playback. Unsupported combinations must remain disabled with a reason.

## Compatibility

Investigate Simple Voice Chat APIs at implementation time and publish the exact tested version range. It remains optional. Retain Minecraft-version-specific audio hooks behind adapters. Check channel layouts and container/editor track limits before offering combinations. Do not substitute whole-desktop loopback for Minecraft-only audio.

## Testing Requirements

- Pass all V1/V2 tests, including lifecycle failure and recovery suites.
- Test USB, integrated and Bluetooth inputs where available, multiple sample rates, permissions and hot-unplug/reconnect.
- Use four-hour impulse tests, including pauses, world changes and device reconnects; inspect decoded audio, not only timestamps.
- Verify clipping/mute/gain semantics and that master and isolated tracks do not duplicate unintended content.
- Import outputs into declared editor versions and verify track names, offsets and duration.
- Test voice-chat absent, present-but-disabled, compatible and unsupported configurations without breaking base recording.

## Completion Criteria

Basic game/mic tracks remain reliable, supported independent sources import correctly, the sync target is met, and reconnects do not shift the remaining timeline. Each offered category or integration has isolation tests. Features that cannot meet separation or timing requirements are documented as deferred, with no working-looking control.

## Explicitly Not Included Yet

No full audio workstation, third-party effects hosting, voice modification, transcription, speaker identification, automatic upload or mandatory voice-chat dependency. Do not promise every Minecraft sound category. No rendering changes beyond what previous versions require.

## Notes for the Next Version

Deliver stable source/track identifiers and a shared clock to V4. Clean visual capture must preserve audio behavior and must not infer audio exclusion merely because a visual overlay is hidden.
