# Version 5 — Native Resolution Pipeline

## Main Goal

Optimize the existing GPU capture/composition pipeline and make recording dimensions independent of the game window without routinely rendering Minecraft twice. V1 already introduced fixed output sizes, GPU scaling, PBO rings and a persistent-mapping path; V5 improves and measures these systems rather than replacing them for novelty.

## User Experience

A creator chooses Performance, Balanced, Creator, Cinematic or Custom. The preset resolves to supported dimensions, frame rate, quality and hardware encoding. A 4K window can produce 1080p footage, and a 1080p window can produce a 1440p file. The latter is upscaled output unless a separately validated higher-resolution scene path exists; it must not be described as additional native scene detail.

Preset names are conveniences, not guarantees. An estimated impact label appears only when measured data supports it; otherwise display Unknown or Not measured for this configuration. Simple mode still requires no knowledge of GPU buffers or encoders.

## New Features

- Explicit recording dimensions and aspect-fit/crop policy independent of window size.
- Capability-aware quality presets with a compact resolved-settings summary.
- Optimized capture backend selection with a reliable existing-path fallback.
- Reproducible comparative performance reports, including results where OBS performs better.

## Technical Work

Treat V4 composition output as the input boundary. Compare reusing its recording target with a dedicated resize target; avoid another copy solely to change class ownership. Specify dimensions, pixel format, color interpretation, orientation and synchronization for every stage.

Benchmark framebuffer blit against shader scaling for both cost and output quality. Keep scaling on the GPU. Investigate encoder-compatible texture formats, GPU color conversion, asynchronous transfers, ring depth, coherent persistent mapping and native encoder interop. A PBO-backed FFmpeg stdin path is not zero-copy: count CPU transport copies and hardware re-upload honestly.

Only introduce a new native backend if measured end-to-end benefit justifies maintenance, resource lifetime and packaging complexity. Preserve VideoEncoder and FrameCapture contracts or evolve them through explicit capability negotiation; retain the portable fallback. All fences, slot leases and cancellation behavior must remain compatible with V2 cleanup and V3/V4 timing/composition.

Distinguish output scaling from independent scene rendering. True higher-resolution world rendering may entail additional GPU work; do not offer it under the ordinary low-impact preset unless its semantics and cost are independently established. Lock output stream dimensions for a session and handle window resize without changing codec parameters unexpectedly.

## Performance Work

Create the first serious OBS comparison suite: same world/camera workload, output dimensions/FPS, codec, encoder, comparable quality, audio tracks and clean-capture equivalence. If OBS cannot match an exclusion, compare ordinary capture separately. Match perceptual quality as well as nominal bitrate; preset names or QP numbers alone are insufficient.

Measure average FPS, 1% lows, p50/p95/p99 frame times, CPU utilization, GPU render/copy/encode utilization, RAM, VRAM, disk throughput, unique captured FPS and duplicates. Use warmed randomized runs, at least three repeats, and report run-to-run variability. Include disabled and enabled-idle baselines, V4 capture and OBS capture. Record OS, hardware, drivers, power settings, VSync, FPS cap and mod list.

Release targets on explicitly supported matched presets: no render-thread waits or IO, stable bounded memory, less than 1% dropped unique frames under sustainable load, and equal or lower game-frame-time impact than OBS within measured uncertainty. A missed target requires published limitations and further optimization or a narrower supported preset; never manufacture a favorable comparison. Preserve previous-version quality and stability regardless of benchmark outcome.

## UI / UX

Keep one preset selector, resolution and frame rate prominent. Show the resolved encoder/quality as optional detail. Custom settings live behind Advanced. Explain upscaling and aspect crop plainly. Presets must not silently change microphone or clean-capture intent; V8 will coordinate full workflow profiles.

## Reliability

Handle GPU allocation failure, device loss, encoder initialization failure and unsupported formats without corrupting the game render state. Probe new backends before recording; avoid risky midstream backend swaps. Enforce explicit memory budgets based on output size and ring depth.

Known risks: driver-specific synchronization, hidden color conversion, VRAM pressure, reduced scaling quality and native interop destabilizing an otherwise reliable path. A faster submission timer is not proof of better whole-game performance.

## Compatibility

Keep OS/GPU-specific encoder interop behind optional adapters. Test NVIDIA, AMD and Intel where hardware is available, including integrated/discrete combinations. Retain Fabric client-only operation and V4 overlay support. Investigate shader/rendering-mod interactions without forcing those mods on users or claiming untested support.

## Testing Requirements

- Pass every V1–V4 regression and long-session audio/recovery test.
- Test 1080p, 1440p and native at 30/60/120 FPS on supported combinations; classify overload rather than pretending all combinations are sustainable.
- Check decoded scaling quality, aspect, orientation, color and timing during resizing/minimization.
- Stress memory allocation limits, queue saturation, context teardown and backend fallback.
- Archive benchmark inputs, settings, raw traces and decoded sample clips so another developer can reproduce the conclusions.

## Completion Criteria

Output dimensions are genuinely independent of the window, supported preset behavior is understandable, copy/pass counts are documented, and each selected backend has proven lifetime/failure handling. Comparative measurements meet the target on the declared support envelope; exceptions are visible. The normal path does not render the world twice.

## Explicitly Not Included Yet

No speculative universal zero-copy claim, mandatory native backend, AI upscaler, second camera, replay renderer, rolling clips or auxiliary depth/mask export. Do not expand to new Minecraft versions simply to avoid optimizing the target version.

## Notes for the Next Version

Expose encoded-stream timing, keyframe boundaries and ownership capabilities to V6. Sharing one capture/encode pipeline should be possible without requiring every backend to expose raw internal pointers or replacing the tested FFmpeg fallback.
