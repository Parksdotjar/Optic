# Version 9 — Advanced Creator Capture

## Main Goal

Add a carefully bounded set of professional capture options while retaining the fast, simple default recorder. Investigate auxiliary render outputs and higher-quality formats separately; ship only combinations with demonstrated correctness, editor usefulness and acceptable cost. V9 is not a commitment to implement every experimental option.

## User Experience

Ordinary Record still produces a standard compatible video. Advanced users can request supported codecs, quality/color formats or specific auxiliary outputs after seeing their compatibility and resource implications. Any automatic overload adaptation is opt-in, constrained by the user's quality floor and reported visibly and in session metadata.

## New Features

- Capability-filtered H.264, HEVC and AV1 choices, with higher bit depth or intermediate/lossless modes only when the full pipeline supports them.
- Optional auxiliary artifacts: HUD, depth, entity mask or players-only mask where practical.
- Explicit color/range handling and verified editor interpretation.
- More robust CFR/VFR timestamp policies and opt-in, documented overload adaptation.

## Technical Work

Extend VideoEncoder capability negotiation with codec, input format, bit depth, color metadata, latency and container compatibility. Do not infer support from a codec name alone: probe the actual profile/format/hardware path. Keep ordinary H.264 defaults and the V5 capture backend intact.

Establish an end-to-end color contract from Minecraft render target through GPU scaling/conversion, encoder and container to editor decode. Test range, transfer function, matrix, primaries and alpha semantics where applicable. Higher-bit-depth output does not manufacture higher-precision source detail; a 10-bit encoder alone does not make HDR. Offer HDR only after meaningful source, tone mapping, metadata and editor behavior are all proven.

Prototype auxiliary outputs as optional capture stages with independent identities and synchronized timestamps in the V8 recording bundle. Define mask labels, depth units/normalization, visibility/occlusion, transparency and resolution explicitly. A useful depth/mask output must preserve its data semantics rather than being passed through an unsuitable lossy color codec. Evaluate formats based on actual editing use and storage cost.

Reuse available render information where possible. If a layer requires extra geometry/world rendering, expose it as an expensive experimental mode or defer it; never add those passes to normal recording. Keep V4 clean visibility policy distinct from auxiliary data generation.

Evolve the shared time model instead of assuming one rendered frame per output interval. Define CFR duplication/drop behavior, VFR timestamp monotonicity, audio mapping and discontinuity handling. For optional overload control, use sustained measurements, hysteresis, user-approved bounds and an audit trail. Changes requiring a new codec configuration should start a validated new segment, not corrupt an existing stream.

## Performance Work

Build per-feature incremental CPU/GPU/VRAM/storage budgets and refuse combinations that exceed declared resource limits. Auxiliary queues remain bounded and may stop the auxiliary output before endangering the main video, with a visible notice. Do not silently degrade the main recording to rescue an optional layer.

Targets: advanced-disabled capture remains within V8 noise, with investigation thresholds of 5% p95/p99 frame-time or 3% 1% low regression. Publish measured costs for every supported layer/codec combination; do not assign all of them the normal low-impact target. Demonstrate bounded memory and no render-thread waiting at the highest supported output load.

For ordinary matched presets, retain V5's equal-or-lower-OBS-impact target and fair quality matching. Adaptation tests must prove reduced backlog without oscillation and must record every quality change. Never equate a correctly stamped 120 FPS stream full of duplicates with 120 unique captured frames.

## UI / UX

All new options belong under Advanced. Show only supported formats and explain disabled ones. Require deliberate enablement of auxiliary files and show expected storage/impact estimates with uncertainty. Offer predictable defaults for editor-friendly output; avoid asking a normal player about color matrices, GOPs or B-frames.

Overload notices should say what changed and why. Users can disable adaptation, choose a minimum quality and select stop-rather-than-degrade behavior. Preset changes must not silently enable HDR, lossless capture or extra layers.

## Reliability

Handle encoder/device loss, invalid color combinations, auxiliary writer failure and disk exhaustion independently where possible. Preserve the main recording and its time mapping. Recovery must understand multiple artifacts and incomplete segments without falsely labelling a whole bundle complete.

Known risks: misleading HDR claims, editor color shifts, inconsistent hardware codec support, huge intermediate files, masks that omit modded entities, and adaptive changes producing uneditable streams. Gate risky combinations behind proven support, not an optimistic toggle.

## Compatibility

Publish exact GPU/driver/encoder/container/editor combinations. Re-test optional Iris/Sodium and content mods for layers affecting render semantics; do not assume a shader's depth buffer matches vanilla meaning. V1–V8 default recordings and profiles must remain valid. Other mods and external editors remain optional.

## Testing Requirements

- Pass all V1–V8 tests with advanced options off and representative supported combinations on.
- Use reference color/range charts and decoded pixel comparisons, then import into tested Premiere/Resolve versions.
- Validate depth/mask semantics with known geometry, occlusion, particles, transparency and modded entities.
- Exercise variable game FPS, long stalls, duplicate frames, pause/world transitions and multi-hour A/V sync under CFR and offered VFR modes.
- Inject sustained overload and verify adaptation boundaries, hysteresis, notifications, segment transitions and recovery.
- Measure CPU/GPU/frame-time/storage impact separately for each auxiliary output and codec.

## Completion Criteria

Every exposed advanced combination is useful in a tested editor and has correct time/color/data semantics. Unsupported experiments remain unavailable. The simple default experience and its performance are preserved. Overload policy is predictable, opt-in and never silently sacrifices quality.

## Explicitly Not Included Yet

No promise of every codec on every GPU, universal HDR, arbitrary compositing layers, offline replay rendering, full video editor or unlimited lossless performance. Do not replace the proven ordinary recorder to accommodate one advanced experiment.

## Notes for the Next Version

Give V10 a tested capability matrix, explicit resource budgets, migration rules and known incompatibilities. Remove or clearly defer experiments that cannot meet production reliability; maturity is not measured by the number of checkboxes shipped.
