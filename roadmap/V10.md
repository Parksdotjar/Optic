# Version 10 — Production Recorder

## Main Goal

Unify V1–V9 into a professional, dependable Minecraft-native recorder for ordinary creator capture. The default experience remains Pause → Record → Play → Stop → Video ready. This milestone is consolidation, compatibility and proof, not a final opportunity to add every conceivable feature.

The performance target is equal or lower Minecraft frame-time impact than OBS for equivalent recording on declared supported hardware. Treat that as an evidence-based release target, never an unconditional marketing claim. Document cases where OBS is faster or more reliable.

## User Experience

A creator installs the client-side Fabric mod, accepts sensible defaults and records. Encoder selection, binary setup, buffering, quality, timing and finalization are handled internally. Advanced audio, clean capture, replay, markers and auxiliary outputs remain optional. Errors offer useful next steps instead of exposing unexplained engineering terminology.

## New Features

- A consolidated support/compatibility matrix and diagnosable capability decisions.
- A user-reviewed, privacy-minimized support report.
- Accessibility, localization, settings migration and support documentation sufficient for routine use.
- Release-grade automated regression and repeatable performance benchmark procedures.

Most work improves existing behavior: startup/shutdown, recovery, encoder selection, sync, GPU/mod compatibility, file operations and UI consistency. No major new recording architecture is implied.

## Technical Work

Audit module boundaries and ownership contracts. Keep Minecraft-version-specific capture/audio/UI hooks isolated from recording, timing, encoding, metadata and storage. Stabilize manifest/profile schemas and migration paths, including safe treatment of unknown future fields and a recoverable backup before migration. Never rewrite users' media as a side effect of settings migration.

Consolidate optional compatibility adapters for Flashback, Sodium, Iris, Simple Voice Chat and common HUD/waypoint mods where meaningful and maintainable. Prefer supported APIs; record tested version ranges and conflict detection. Missing integrations must not disable base recording. A compatibility issue should have a targeted workaround, not an unconditional global mixin override.

Audit FFmpeg acquisition provenance, pinned releases, integrity verification, cache repair, update policy and distribution/licensing obligations. Keep binary handling internal and safe. Validate subprocess cleanup and normal/abnormal shutdown with real drivers, including persistent mapping lifetime and abandoned recordings.

Generate support reports from structured diagnostics: Minecraft/Fabric/mod version, OS, GPU/driver, capture backend, encoder/binary version, resolved recording settings, drops/duplicates, relevant errors and a bounded log excerpt. Redact tokens, account identifiers, private addresses, world names, chat, microphone content and identifying paths by default. Preview before export; do not automatically upload reports.

## Performance Work

Maintain a repeatable four-state suite: recorder disabled, enabled but idle, actively recording, and OBS recording. Define whether disabled means absent or loaded-but-off and keep the baseline consistent. Compare the same scene, movement, warmup, output size/FPS, codec, hardware encoder, quality, audio tracks, FPS cap and presentation settings. Publish any unavoidable differences.

Test NVIDIA, AMD and Intel across integrated, low-end, midrange and high-end systems where available. Declare untested cells rather than generalizing from one GPU. Capture average FPS, 1% lows, p50/p95/p99 frame time, stutter counts, unique captured frames, duplicates/drops, CPU/GPU utilization, RAM/VRAM and disk throughput. Include simultaneous Flashback and shader scenarios as separate workloads.

Run at least three randomized warmed repeats per configuration, multi-minute captures and long-session soak tests. Archive raw traces, output quality samples, settings and reproducible workload instructions. Compare within run-to-run uncertainty; a tiny numerical advantage is not proof. Account for VFR/CFR differences and include equivalent output quality, not just bitrate.

Release gates: no render-thread IO/waiting, bounded resource usage, no material idle regression beyond baseline noise, preservation of prior supported-preset budgets, and evidence for the OBS target on each advertised configuration. A regression above 5% p95/p99 frame time or 3% 1% lows versus the last stable equivalent configuration requires resolution or explicit support qualification. Publish unfavorable results and narrower support where necessary.

## UI / UX

Simple settings remain a compact set: Quality, Resolution, Frame Rate, Microphone, Advanced and Open Recordings. Preserve the Minecraft-style eye/record button and cog arrangement. Keep neutral, restrained visuals and consistent focus/hover feedback. Show advanced features only when requested; do not create a dashboard of every internal subsystem.

Support keyboard navigation, narration, configurable keybinds, readable GUI scaling and status cues that do not rely only on red/green color. Localize user-facing strings and test long translations. No normal workflow should require understanding FFmpeg, NVENC/AMF/QSV, bitrate, GOP, B-frames, framebuffers, PBOs or muxing.

## Reliability

Perform a full failure audit covering preparation cancellation, rapid toggles, world/server transitions, permissions, full disks, device changes, encoder crashes, GPU/context loss, clip pinning, metadata migration and interrupted finalization. Recover what is reasonably recoverable, retain failed sources and avoid overwriting existing videos. State unrecoverable cases honestly.

Known risks include an unmaintainable compatibility matrix, stale drivers/binaries, difficult-to-reproduce native races, misleading benchmark claims and settings complexity accumulated over releases. Bound support promises, freeze optional feature scope and prioritize reliability fixes over new controls.

## Compatibility

All popular-mod adapters remain optional and client-side. The original target stays Minecraft 1.21.11 until an explicit port is separately accepted; the roadmap does not authorize broad multi-version support. If later ports are undertaken, require the same regression suite per version and keep compatibility-layer changes from rewriting the core recorder.

Maintain backward readability of V1–V9 finalized videos and supported metadata. Test profiles created on different supported hardware, absent optional mods and older settings schemas. Clearly distinguish supported, degraded and unavailable configurations.

## Testing Requirements

- Pass all V1–V9 functional, failure, synchronization, privacy, file-operation and performance suites.
- Test remapped production JAR installation in clean launcher instances, not only development launches.
- Exercise first-run binary setup, offline use after setup, cache corruption, denied permissions and update/migration rollback.
- Run eight-hour recordings, repeated lifecycle cycles and actual process-crash recovery on representative hardware.
- Test accessibility, localization, UI scaling, optional-mod matrices and all diagnostics redaction fields.
- Reproduce benchmark findings on another machine/operator where possible and retain evidence for release claims.

## Completion Criteria

The ordinary capture flow works with nearly zero setup on the published support matrix. Long recordings remain synchronized and recoverable where technically possible; settings and file operations preserve user data. Advanced features are optional, truthful and bounded. Production install, accessibility, migration and compatibility tests pass. Performance claims match published reproducible results, including documented exceptions where OBS wins.

## Explicitly Not Included Yet

No mandatory cloud account, telemetry upload, streaming platform, scene compositor, full video editor, endless integrations or promise to replace OBS for non-Minecraft capture. No automatic support claims for untested GPUs, editors, mods or Minecraft versions. No feature may bypass the performance/reliability gates merely to complete a checklist.

## Notes for the Next Version

There is no implied V11 feature list. Continue maintenance, security/binary updates, measured performance improvements and separately scoped ports. New features should enter only with a demonstrated creator need, explicit resource budget and a regression plan. Preserve the simple Record/Stop experience as the product's permanent foundation.
