# Version 2 — Recorder Polish & Reliability

## Main Goal

Make the V1 recorder dependable enough for long sessions, without adding new creator workflows. This is a plan, not an implementation or a statement that these capabilities already work. Product versions V1–V10 are Optic milestones, not Minecraft versions; the initial supported game remains Fabric client-side Minecraft 1.21.11.

V1 requirements remain the prerequisite; no replacement V1 document is being created in this roadmap. The current alpha still documents unfinished Minecraft audio and incomplete physical-microphone validation. Close those V1 acceptance gaps before declaring V2 complete; do not treat a video-only alpha as the finished V1 baseline. Preserve the accepted vanilla-style eye/record button beside Advancements and cog beneath it.

## User Experience

Record starts once, visibly acknowledges preparation, and reaches a truthful recording state. Stop acknowledges saving immediately and eventually reports either a saved video or a recoverable interruption. Repeated input cannot start duplicate sessions. Pausing, leaving a world, and quitting never strand the UI in a false REC state.

Keep the normal indicator at `● REC 04:21`. Optional details reveal actual output FPS, resolution and selected encoder. A compact completion card shows duration, dimensions, frame rate, Open Video and Open Folder only after the output is validated.

## New Features

- A bounded lifecycle for preparation, recording, stopping, finalization and failure, including cancellation of preparation.
- Completion feedback with actionable file links and a concise recovery result on next launch.
- Internal capture, queue, encoder, storage and game-frame telemetry; diagnostics stay hidden by default.
- Capability-aware encoder choice and a sensible default quality policy, with explicit fallback feedback.

## Technical Work

Extend RecordingManager and RecordingSession rather than introducing a second recording engine. Give each session an identity so stale asynchronous callbacks cannot change a newer session. Define buffer ownership, cancellation, resource disposal and terminal outcomes for every state transition. Release mapped buffers only after their consumers finish; never wait for encoding on the render thread.

Define policy for each boundary: pause continues recording; world switches remain on the same fixed output canvas; disconnect records the visible menu until Stop unless an explicit setting says otherwise. Normal exit should finish within a documented deadline while the UI remains responsive; abnormal exits retain recoverable sources.

Improve FFmpegManager with bounded downloads, verified cache reuse and actionable errors. Probe actual requested encoder configurations, not just codec listings; invalidate cached results when driver, device, binary or settings change. Reuse the software fallback. Do not attempt an unsafe codec switch inside an already-open stream.

Add structured session manifests, recovery ownership locks and schema versioning. Validate final output before removing recoverable sources. Distinguish submitted, accepted, encoded and decoded frame counts; pipe throughput alone is not encoded FPS.

## Performance Work

Measure average/max and percentile capture cost, observed transfer latency, queue depth/high-water mark, duplicate and dropped frames, encoder throughput, disk write rate and full game-frame distributions. Aggregate counters off-thread; avoid logging or allocating strings every rendered frame. Preserve persistent PBO capture and its GL fallback.

Provisional acceptance targets on declared supported presets: UI acknowledgment within 100 ms; stop acknowledgment within one rendered frame; no unbounded memory growth; under 1% dropped unique frames in sustainable steady-state workloads. Across three warmed runs, investigate any p95/p99 frame-time regression above 5% or 1% low regression above 3% versus the equivalent V1 configuration. Report startup/finalization separately. These are engineering gates, not performance claims.

## UI / UX

Keep preparation/saving states on existing controls and use tooltips for detail. Show unavailable functionality honestly. Completion feedback must not steal movement focus or fill the pause menu. Advanced telemetry belongs behind a deliberate diagnostics action, not in the normal HUD.

## Reliability

Handle rapid toggles, pause/unpause, disconnect, world replacement, exit, encoder death, denied microphone access, microphone unplug/replug, default device changes, disk exhaustion and failed finalization. Audio failure must not invalidate video. Disk failure must stop capture promptly and preserve readable fragments. Every failure needs a bounded cleanup path and a useful message.

Known risks include asynchronous callback races, driver-dependent mapped-buffer lifetimes, blocked process pipes, and recovery mistaking a live recording for an abandoned one. Fault injection must exercise each of these, including failures during cleanup itself.

## Compatibility

Keep Minecraft hooks isolated in the existing compatibility layer. Check pause widgets alongside Flashback without relying on fixed coordinates. Verify encoder behavior on NVIDIA, AMD and Intel hardware where available; otherwise mark that device path unverified. Never require another mod or a server component. No automatic expansion to other Minecraft versions.

## Testing Requirements

- Re-run all V1 functional tests and real audio/video recording checks.
- Perform 100 rapid start/stop cycles, including toggles during preparation and saving.
- Run four-hour recordings and repeated world/disconnect/pause transitions.
- Inject full disk, permission changes, killed FFmpeg, stalled pipes and device loss at every lifecycle stage.
- Test actual crash/relaunch recovery and verify duration, decodability, track presence and source retention on failed recovery.
- Collect disabled, idle and recording frame-time traces; report p50/p95/p99, average FPS and 1% lows.

## Completion Criteria

All V1 functionality passes. Every lifecycle transition has an automated or documented manual test, repeated cycles release resources, four-hour supported-preset recordings finalize correctly, and recoverable failures never leave a stuck recording state. Default encoder/quality choices are validated on the published support matrix. Performance gates are met or the affected preset is clearly excluded from supported operation.

## Explicitly Not Included Yet

No replay buffer, markers, library, clean-HUD capture, new codecs, elaborate profiles, scene system or editing tools. Basic audio correctness remains a V1/V2 obligation; category splitting and professional audio controls belong to V3.

## Notes for the Next Version

Provide V3 with stable session clocks, track identities, device-change events, manifests, fault-injection tools and long-session reference recordings. Preserve those contracts while expanding audio rather than replacing lifecycle management.
