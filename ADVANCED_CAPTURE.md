# V9 advanced creator capture

This is a development implementation for Minecraft 1.21.11, not certification of every V9 experiment. Ordinary recording keeps its existing H.264 default and conversion. Advanced options apply to subsequent recordings. No release JAR is generated by this work.

## Formats

Open Recording → Advanced → Advanced formats / color / overload. Stop recording/replay before changing options. Check hardware formats, then click Format to cycle through successful candidates. Discovery tests HEVC and AV1 implementations for NVIDIA NVENC, AMD AMF and Intel QSV. Auto retains the existing H.264 hardware detection and software fallback.

An encoder appearing in FFmpeg's list is insufficient: each candidate must encode six RGBA test frames at the requested resolution/FPS, mux fragmented MP4 and fully decode it. Probes run on a bounded background worker, have timeouts, remove their temporary video and retain diagnostic logs under config/optic-tools/advanced-probes. Closing the screen cancels discovery. Recording startup checks the selected advanced encoder again; failure produces a notice and falls back to H.264. A successful six-frame probe proves basic operation, not sustained throughput or editor compatibility.

All exposed output is 8-bit YUV 4:2:0. HEVC uses the hvc1 MP4 tag. B-frames remain disabled and the existing keyframe/recovery policy remains intact. Both basic audio sources still mux as separate named AAC tracks. Replay deliberately falls back to H.264 with feedback until advanced-codec segment/export compatibility has its own validation.

## Color

Existing conversion remains the default. Explicit SDR assumes the final captured RGB bytes represent SDR sRGB: BT.709 primaries, sRGB transfer and a BT.709 matrix into limited-range YUV. It sets frame properties and output metadata explicitly; it does not perform HDR tone mapping or a transfer-function conversion. RGB alpha is discarded. The same-size FFmpeg scale filter performs matrix/range conversion, not resolution resizing; spatial resize remains on the GPU.

Shader packs or rendering mods that change the source color contract need independent testing. Selecting SDR cannot make unknown HDR/linear input correct. There is no HDR, 10-bit or wide-gamut claim. Reference: official [FFmpeg filter documentation](https://ffmpeg.org/ffmpeg-filters.html) for scale and setparams.

## Timing and overload

The existing monotonic recording timeline schedules constant-frame-rate output. Missed frame deadlines repeat the last available frame; excess capture work is dropped through bounded queues. Audio retains its aligned timeline. This does not assume that Minecraft delivers every rendered frame exactly on schedule. The existing greater-than-five-second capture-gap protection remains.

Optional Stop on sustained duplicates stops after more than 10% repeated output frames in three consecutive sampled windows of at least five seconds. A healthy window resets the count. It is disabled by default. The encoder worker computes the condition; the manager handles the stop and ordinary finalization. Feedback and manifest stop reason make the action visible. This indicates sustained capture/output starvation, not a definitive diagnosis of the GPU encoder. There is no silent quality or resolution reduction, and no automatic adaptation UI.

## Auxiliary output investigation

The current PBO path reads the final color attachment. Clean-capture filtering controls GUI submission; it does not produce independent HUD or entity textures. A meaningful depth export needs projection/units, opaque versus transparent depth semantics and shader compatibility. Entity/player masks require draw identity, correct occlusion and additional attachments or passes. A screenshot recolored as a mask would be incorrect.

These paths remain unimplemented pending measured GPU, VRAM and transfer budgets. No second world render, auxiliary readback or extra per-frame allocation was added. HDR, lossless/intermediate output, native editor certification, VFR output and adaptive quality are also deferred; there are no controls pretending these features work.

## Validation and release gates

On this Windows machine (RTX 5050 Laptop GPU, NVIDIA driver 610.74), actual HEVC NVENC, AV1 NVENC and HEVC QSV probes succeeded. AMF and AV1 QSV probes did not succeed and are not advertised as available. Results are specific to this machine and FFmpeg build.

The integration harness encodes 60 chart frames through libx264 and each successful hardware candidate, finalizes with separate synthetic stereo game/mono microphone sources, fully decodes the result, checks six color patches within eight RGB levels, and checks limited-range/BT.709/sRGB metadata after muxing. Physical game-process audio integration also passes. These short synthetic files do not establish multi-hour physical microphone synchronization or editor import correctness.

Live Minecraft six-second 1080p30 HEVC and AV1 recordings exercise the unchanged PBO capture path and completion lifecycle. Unit tests cover sustained-overload thresholds and resets, configuration defaults and encoder/color options. Previous replay and recovery integrations still pass.

Remaining gates include Premiere/Resolve/After Effects import on actual installed versions; AMF and additional Intel/NVIDIA devices; shader color checks; multi-hour combined workloads; sustained hardware throughput and fair OBS comparisons. HEVC/AV1 decode during validation or thumbnail extraction can cost more than H.264. Do not claim lower frame-time impact without equivalent measurements. See PERFORMANCE.md.
