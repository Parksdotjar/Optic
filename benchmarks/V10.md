# V10 reproducible benchmark protocol

Use the existing V5 tools with the stricter V10 acceptance procedure below. Never measure while another test, compilation, codec probe or export is running. The built-in trace measures render-loop intervals, not presentation latency or total GPU cost.

## Four conditions

1. `disabled`: Optic absent, with an external frame collector.
2. `idle`: Optic loaded, replay OFF, no capture.
3. `record`: Optic capturing the matched target settings.
4. `obs`: Optic loaded but idle/replay OFF; OBS already recording the matched scene.

Use the same external presentation collector for all four conditions. An Optic hook cannot measure a mod-absent baseline; do not relabel idle as disabled. The internal `idle`, `record`, `obs` harness provides supplemental traces, never evidence that OBS was actually running. Configure and verify OBS manually. Do not run both encoders in the OBS condition.

## Workload and order

Use the same disposable world snapshot, saved position, weather/time/entities, movement path, resource packs, shader state and chunk distances. Restore the snapshot before every repeat. Keep the same window size, fullscreen state, VSync, FPS cap, driver, power profile, background tasks and thermal starting condition. Archive these in a human-reviewed environment record without private server/account data.

Choose an order using a recorded random seed and shuffle all four conditions once per block; run at least three blocks. Warm the world/chunks for at least 15 seconds and encoding for at least five seconds. Capture at least 120 measured seconds per run, preferably 300 for thermal comparisons. Keep foreground focus and reject overflow/unfocused traces, with the reason recorded. Do not discard otherwise unfavorable runs.

Example supplemental run: `gradlew.bat runClient -Pbenchmark=record -PbenchmarkWorld="Optic V4 Validation" -PbenchmarkSeconds=180 -PbenchmarkLabel=record-block1`. This harness uses 1280×720 game rendering, Balanced 1080p60 H.264 Auto/Standard, full HUD and audio OFF. It resets advanced color/overload/replay in memory and closes its own client. It is one defined workload, not a universal recommended configuration. Other resolutions/codecs/audio require their own matched runs and archived resolved manifests.

## Summaries

`gradlew.bat benchmarkSummary -PtraceDirectory="run/v5-benchmark"` writes summary.csv. Each trial directory needs environment.txt (`mode`, `samples`, `unfocused=false`, `overflow=false`) and frames.csv with `frame,ns` header, zero-based contiguous indices and positive frame intervals. For external collectors, convert the same interval definition consistently in every condition and document that conversion; never combine internal-render and presentation traces in one comparison.

The tool bounds files/sample counts, rejects invalid sequences, reports exact nearest-rank p50/p95/p99, average FPS, slowest-1%-mean FPS and stutters over 50 ms. It marks runs under 120 seconds, unfocused/overflowed or missing validation metadata ineligible, and reports eligible counts for all four states. It does not decide visual equivalence or declare a winner. Keep raw traces alongside summaries. Existing V5 scripts remain for historical comparisons.

Measure CPU load, GPU render/copy/encode utilization, working/private memory, dedicated/shared VRAM and disk throughput using the same external sampler. Optic metrics add queue high-water, accepted/unique FPS, drops, duplicates and bitrate. Zero or missing external counters are not valid utilization measurements. Inspect output quality, dimensions, actual cadence, audio tracks and color contract; equal bitrate or quantizer numbers alone do not imply equivalent quality.

## Decision rules

Report all repeats and median plus range or confidence intervals for each state. Compare Optic versus OBS and versus the previous stable equivalent setup. A regression over 5% p95/p99 frame time or 3% slowest-1% FPS needs a fix or an explicit narrowed support statement. Idle changes should remain within baseline noise. Compare unique frames, not merely CFR output FPS; duplicates can conceal overload. There is no universal impact estimate.

Perform eight-hour A/V soak tests separately. Repeat Flashback, shader/clean-capture, replay and export workloads as separate scenarios rather than silently changing the ordinary recording baseline. Obtain an independent machine/operator reproduction before advertising broad results. Current evidence is insufficient for an equal-or-faster-than-OBS claim.
